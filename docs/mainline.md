# 神州长卷寻墨记

依据《水墨神州五大墨灵空间主线策划》的五章结构，实现五处风格化三维记忆空间。主线入口默认进入三维探索，旧版二维交互手记作为辅助体验保留。

## 体验入口

打开 `2d/mainline.html`，或从首页选择“主线游历”。通过 HTTP 服务运行可使首页、主线和行囊共享稳定的同源存储。主线操作不需要登录，也不调用付费 AI 接口。返回地图后，下方主线面板显示五处古建的修复进度。

## 已实现内容

- 总览以“神州长卷寻墨记”为开场，说明执笔人身份、长卷褪色、小墨灵失忆与行动目标；章节卡片展示情感主题、人物困境、任务数量和信物。
- “游历手记”可切换阅读五章人物愿望、连续任务、空间动线、环境反馈和建筑观察；未通关章节不展示信物回声和小墨灵结局记忆。
- 五个章节入口统一进入 `journey-3d.html?chapter=章节ID`。共享 Three.js 运行时负责第三人称移动、拖动环视、远近调整、分层行走、碰撞与交互。
- 三维场景包括分层楼阁与两侧石阶、拱桥与桥下记忆通道、回廊水院、分层木塔及圆形土楼。场景使用本地程序化几何、纹理、水面着色、光照、阴影、雾、粒子和灯光构建，无外部 CDN 或付费服务。
- 近距离按住 E 互动；Q 显示小墨灵引导。机关包含纹片旋转、框景视角对齐和线索次序拼接；关键人物以固定对白推进剧情。WASD / 方向键移动，Shift 疾行，拖动环视，滚轮远近，Esc 暂停。手机提供触摸摇杆和互动按钮。
- 三维探索在完成物件交互和任务时保存检查点，移动期间定期保存位置，退出时再次保存；刷新或重新进入可继续。三维进度与二维手记各自保存途中状态，共用章节完成记录和信物。
- “打开交互手记”进入原有规则驱动的逐步交互版本，可独立完成主线，途中操作自动保存。
- 黄鹤楼、赵州桥、拙政园、应县木塔、福建土楼，按顺序解锁，共十九个连续任务。
- 每个任务包含多个物件操作，后续任务需要前一个任务完成。错误顺序不会清空已有操作。
- 开窗与光路、桥面复位与灯光、园林四季与水路、木塔楼梯与账册、土楼开门与院灯均随任务状态变化。
- 三层提示：观察方向、线索解释、下一操作；不以模型输出判断通关。
- 每次正确操作自动保存，刷新、退出章节后可续玩；兼容旧版已完成章节记录。
- 五件信物和记忆保存在主线行囊，并合并到首页已有背包读取流程。登录后的同步沿用项目现有机制。
- 第五章需要前四章信物，完成后在章节总览展示“执笔归来”结局，无第六个副本。
- 小屏布局、键盘焦点约束、Escape 关闭和状态播报。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `2d/mainline.html` | 总览、行囊和章节弹层 |
| `2d/mainline-data.js` | 剧情、任务描述、知识与信物 |
| `2d/mainline.js` | 任务规则、存档校验、提示、状态场景 |
| `2d/mainline.css` | 交互场景、物件操作和响应式样式 |
| `2d/journey-map.js` | 地图进度与首页背包读取 |
| `2d/journey-3d.html` / `.css` | 三维界面、机关面板、暂停、字幕与移动端操作 |
| `2d/journey-3d-data.js` | 五章空间坐标、19任务节点、机关条件和固定对白 |
| `2d/journey-3d.js` | 三维建筑生成、渲染、行走、相机、碰撞、任务和检查点 |
| `2d/ink-human.js` | 真人扫描头部加载、古风衣装、发型、手部、关节动作和眨眼 |
| `2d/assets/characters/` | 本地扫描几何、皮肤颜色/法线贴图和素材署名许可 |
| `2d/vendor/GLTFLoader-r128.js` | 与现有 Three.js 匹配的本地模型加载器 |

存档仍使用 `inkJourneyProgressV1`，交互手记记录 `progress[章节ID] = { task, actions }`，用 `progressSchema: 2` 标记新的三任务黄鹤楼结构。旧版第四任务的进度合并到第三任务，旧版第三任务的导航操作原样保留，完成记录不清空。`completed` 仅接受从第一章开始连续完成的合法章节 ID。进度目前保存在当前浏览器，不能作为服务端奖励或身份认证的可信依据。

三维中途存档另用 `inkJourney3DProgressV1`，按章节保存 `{task, action, position, finished}`，在三维通关后合并到原主线的连续完成记录，不覆盖二维手记。检查点只在机关成功或对白完成后推进；中途离开未完成机关时，返回本次机关前的有效状态。存储失败会在界面提示，浏览器存档不作为可信的服务端奖励凭据。

## 人物表现

玩家和故事人物采用真人比例躯体、带褶皱的程序化衣装、独立手指、束发及真人扫描头部。皮肤包含本地颜色贴图与法线细节；扫描原作是 Lee Perry-Smith / Infinite Realities 的胸像，已裁去肩部并保留 UV，用 CC BY 3.0 署名许可分发。素材出处和改编说明见 `2d/assets/characters/ATTRIBUTION.md`。当前故事人物共用同一份示例扫描脸，通过衣装和发色区分，尚不是定制的中国古风角色阵容。

开场选择“先看人物”，或进入游戏后点“人物近览”/按 C，可切换全身、面部特写和转身查看。近览不会改变位置、任务或存档。走路时手臂与腿部摆动，衣摆轻微运动；待机有呼吸、轻微转头及眼部眨动。动作是程序化关节动画，尚未使用完整动作捕捉与表情绑定。面部资源失败时使用备用人体模型，继续保留游戏流程；近览会明确显示加载状态。

## 验证

安装或提供 Playwright 后运行 `node scripts/verify-mainline.cjs`。脚本通过本地请求映射验证页面，不启动 Flask、不改数据库、不调用 AI。覆盖五章手记与任务数、章节解锁、黄鹤楼三维入口、交互手记错误顺序、刷新续玩、十九任务通关、五件信物、结局、地图/背包接入、小屏溢出、损坏存档及黄鹤楼旧进度迁移；截图写入 `tmp/journey/`。该脚本不验证可探索关卡内部的完整通关与中途恢复。

`node scripts/verify-journey-3d.cjs` 验证五章 WebGL 渲染、真实机关 UI、错误次序、19任务、逐物件检查点、信物和结局记录以及手机开场布局。测试在远距离节点间恢复玩家位置，以检查所有交互分支，不等同于玩家完整行走测试。`node scripts/verify-journey-paths.cjs` 复用生产行走高度与边界函数，遍历可达区域，验证所有任务目标能在允许互动距离内接近；该检查未包含渲染中的柱体碰撞。

`node scripts/verify-human.cjs` 验证本地面部/贴图成功加载，玩家和 NPC 均使用扫描头部，全身/特写/转身、开场与游戏返回、人物移动、小屏显示及扫描资产不可用时的降级；截图保存在 `tmp/human/`。

## 后续制作范围

### 大地图导航修复

首页地图优先使用 `ditu/` 中的透明 PNG 板块；其余旧 JPEG 板块按省份填色恢复显示和拾取遮罩。省份背景与景点图标引用使用工作区实际存在的扩展名。像素拾取固定使用布局坐标，避免悬浮抬升使小板块移出点击点。主线进度默认折叠，操作其按钮或链接不会继续触发底下的省份。

运行 `node scripts/verify-map.cjs` 可在离线环境验证34个板块逐一点击、预览、省内入口、景点资源、返回及进度面板事件隔离。首页 Three.js 已改为本地文件，避免 CDN 不可用导致菜单失效。

当前三维版本是风格化可玩原型，建筑使用程序化场景片段，并非测绘复原或高精度商业游戏成品。高精度模型、完整角色骨骼动画、镜头避障、真实水面反射、配音、丰富空间音效和深度差异化机关仍可继续迭代。框景目前用机关面板调整对应视线；非场景相机实时摄影测量。环境声为可选的本地合成氛围音，未调用语音服务。五章实际时长与不同设备的性能还需用户试玩，不把策划中的十五至二十分钟当作已实现指标。历史资料与具体构件仍需考证。
